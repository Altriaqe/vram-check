## 1. 背景与问题

跑模型时 `CUDA out of memory`，任务管理器只告诉你"已用 19.8GB"，不告诉你**是谁**。

- "专用 GPU 内存"列默认隐藏，要右键加列；
- 加了列也是一堆 `python.exe`、`chrome.exe`、`dwm.exe`，不分组、不解释；
- 猜到是哪个 `python.exe`，也不知道它是"三小时前卡死的训练脚本"还是"同事在用的 Jupyter 内核"；
- 关掉之后，显存不一定立刻回来，于是又怀疑"到底释放了没有"。

**用户真正要回答的不是"显存用了多少"，而是"我现在要腾出 X GB，关哪个最安全、最有效？"**

这是一个**决策 + 执行**问题，不是观测问题。这是本产品的立足点。

## 2. 定位与非目标

### 2.1 定位纪律

> 任何一个功能，如果不能让它**更快**（少一步、少一秒）或**更懂**（少一次搜索、少一次犹豫），就不做。

这条优先于"竞品有所以我们也要有"。

### 2.2 三条硬约束（架构级，非功能附注）

| 约束 | 预算 | 说明 |
|---|---|---|
| 体积 | **单文件 ≤ 2 MB** | 不内嵌字体（用系统微软雅黑），原生控件，LTO + strip |
| 速度 | 冷启动 **≤ 100 ms**；单次采样 ≤ 10 ms | 常驻 PDH 查询，不重建 |
| 占用 | 单进程（UI + 采样两线程）；**默认不常驻**；失焦停止轮询 | 不装服务、不注入、不写注册表 |

### 2.3 非目标

- ❌ 超频 / 风扇曲线 / 功耗墙
- ❌ 游戏 FPS / 帧生成监控
- ❌ CUDA kernel / 显存块级剖析（Nsight、PIX 的地盘）
- ❌ 多机 / 集群显存监控
- ❌ **模型级显存拆解**（gputaskman 已做得很深，正面拼是自杀）
- ❌ "一键清理显存"这类伪科学按钮（见 §6.6）
- ❌ 驱动安装、系统优化、后台偷跑

## 3. 用户与场景

| 画像 | 诉求 | 对设计的约束 |
|---|---|---|
| **P1 本地 AI 开发者**（主） | 快速定位残留进程 | 能忍信息密度 |
| **P2 共用机 / 远程桌面使用者** | 找出别人留下的僵尸进程 | **不能依赖 OpenGL**（这台机器就有 4 个虚拟显卡） |
| **P3 普通用户** | "这堆进程是啥，能不能关" | **易懂的试金石** |
| **P4 支持/运维** | 截图发给同事 | 截图要能看懂 |

> P3 是最重要的设计约束：**P3 能看懂，P1 一定看得懂；反之不成立。**

**核心场景**：跑模型前发现显存只剩 4GB → 打开 → 看三列 → 找到两个无窗口的 `python.exe` → 勾选 → 关闭 → 看数字降下来。全程 ≤ 30 秒，不看说明书。

## 4. 竞品与借鉴

### 4.1 位置

竞品拥挤在"观测"，稀疏在"翻译 + 行动"。真正的对手不是某个软件，是用户的**放弃行为**：

| 替代行为 | 我们怎么赢 |
|---|---|
| 打开任务管理器 → 看不懂 → 关掉 | 同样的信息，多一句人话 |
| 敲 `nvidia-smi` → 看不到进程 | 把总量拆到进程，说明未归属 |
| 装 gputaskman → 英文 TUI → 放弃 | 双击即用，零学习成本 |

### 4.2 技术借鉴清单

| # | 借鉴点 | 出处 | 不这么做会怎样 |
|---|---|---|---|
| T1 | 主口径 `Local Usage`，`Dedicated` 只兜底 | 本机实测 | 各进程相加**超整卡**（实测 128.5%） |
| T2 | 进程名走 **Toolhelp32 快照**，不走 `OpenProcess` | hypomnesis | SYSTEM 进程全显示 `?` |
| T3 | PID 4 标成 `[kernel]` | hypomnesis | 和无权限进程混淆，像病毒 |
| T4 | 先 DXGI 拿 LUID，再按 LUID 过滤实例 | hypomnesis | 多显卡数据串行 |
| T5 | `PdhAddEnglishCounter` 作保险 | 通用实践 | 本地化系统可能读不到（本机不需要） |
| T6 | 采样失败整次跳过，**绝不写 0** | hypomnesis | `0 GB` 被当真，误判"没占用" |
| T7 | 计数器缺失时降级不崩溃 | hypomnesis | 老机器启动即崩 |
| T8 | 采样有预算 | gputaskman | 进程多时界面卡住 |
| T9 | 明确写 out-of-scope | 两者 | 用户以为能看到"哪个贴图占 2GB" |
| T10 | JSON 快照 + diff | gputaskman | P1 再说 |

## 5. 技术基座与口径

### 5.1 数据源

| 通路 | 能给什么 | 用途 |
|---|---|---|
| **PDH 性能计数器** | 每进程显存、GPU 引擎占用、整卡已用 | 主力，免管理员（实测 `Elevated=False` 可读） |
| **DXGI** | 适配器枚举、LUID、**显存容量** | 多卡归属 + 容量 |
| Toolhelp32 / 进程 API | 名字、路径、父进程、命令行、签名 | 解释层地基 |

```
\GPU Process Memory(pid_<PID>_luid_0x<H>_0x<L>_phys_<N>)\Local Usage   # 主口径
\GPU Process Memory(...)\Non Local Usage                                # 共享内存
\GPU Adapter Memory(luid_..._phys_N)\Dedicated Usage                    # 整卡基准
\GPU Engine(pid_..._phys_0_eng_<N>_engtype_<T>)\Utilization Percentage  # GPU%
```

**两个格式差异**：`GPU Engine` 实例名比 `GPU Process Memory` 多 `_eng_N_engtype_XXX` 两段，**解析器不能复用**。

### 5.2 口径（本产品最重要的技术决策）

实测（RTX 4070 Laptop 8GB，空闲态，同一时刻）：

| 口径 | 进程合计 | 占整卡 718 MiB | 判定 |
|---|---|---|---|
| `Local Usage` | 675 MiB | **93.9%** | ✅ 主口径，可加、可解释 |
| `Dedicated Usage` | 923 MiB | **128.5%** | ❌ 重复计入共享 surface，不能相加 |

交叉验证：PDH 整卡 718 MiB vs `nvidia-smi` 713 MiB，差 **0.7%**。

**规则**：
- 主界面只出现 `Local`；
- `Dedicated` 只在"技术详情"里出现，并标注"任务管理器口径"；
- 未归属 = 整卡 − Σ(本地)；若为负，显示"口径异常"而不是负数。

### 5.3 显存容量必须走 DXGI

WMI 的 `Win32_VideoController.AdapterRAM` 在 >4GB 的卡上会截断——本机实测报 **4.00 GB**，实际 **8188 MiB**。容量只能取 `DXGI_ADAPTER_DESC1.DedicatedVideoMemory`。

> M1 实测补充：同一台机器上 DXGI 报 **7948 MiB**（界面显示 7.76 GB），比 nvidia-smi 的 8188 MiB 少约 240 MiB，差额是驱动保留，不是截断。我们显示 DXGI 的"可用显存"，并在 F-33 帮助页解释与任务管理器的差异。

## 6. 产品方案

### 6.1 界面：就三列

```
┌ 显存哨兵 ──── RTX 4070 Laptop 8GB ─── 已用 0.70 / 8.00 GB ─────┐
│                                                                 │
│   程序                    占用        描述                       │
│  ─────────────────────────────────────────────────────────────  │
│  ● python.exe × 3        5.9 GB   PyTorch 训练，GPU 92%，前台   │
│  ● chrome.exe × 12       1.6 GB   浏览器后台标签页，可关        │
│  ● dwm.exe               0.2 GB   桌面合成，系统必需，不能关    │
│  ● Code.exe              0.1 GB   编辑器，无 GPU 活动           │
│  ○ 未归属                0.04 GB  驱动与共享资源，无法关闭      │
│                                                                 │
│                          [ 关闭选中 ]   [ 刷新 ]   [ ⚙ ]        │
└─────────────────────────────────────────────────────────────────┘
```

点击某行，底部展开一句解释（不弹窗、不切页）：

```
python.exe (PID 24168) —— 父进程 Code.exe，命令行含 train.py
训练正在进行，结束会丢失进度。[ 仍然关闭 ]
```

**只显示有显存的进程**：实测 314 个进程里只有 32 个持有 GPU 实例，不需要虚拟滚动、不需要分页。

### 6.2 三条核心流程

**A. 释放（最高频）**：多选 → 关闭选中 → 优雅关闭优先 → 3 秒未退再问强制 → 显示**实测**释放量。

**B. 这是啥**：单击任意行 → 底部一句话 +（点开）依据。

**C. 谁在涨**（P1）：切"历史"页 → 30 分钟曲线 → 斜率 TOP 3。

### 6.3 解释引擎（四层）

| 层 | 来源 | 覆盖 | 示例 |
|---|---|---|---|
| L1 规则库 | 内置 TSV，200 条 | ~90% | `dwm.exe` → "桌面合成，系统必需，不能关" |
| L2 签名 | `WinVerifyTrust`（实测可用） | 已签名程序 | "NVIDIA 驱动组件，关掉会被重新拉起" |
| L3 启发式 | 父进程 + 命令行（实测非提权可读）+ 窗口 + 时长 + GPU% | 兜底 | "父进程 VS Code，含 train.py，GPU 92%" |
| L4 LLM（可选） | 用户主动点"不认识？" | 长尾 | 仅发脱敏元数据，默认关闭 |

**风险分级**：

| 等级 | 判定条件 |
|---|---|
| ⛔ 禁止 | `csrss/wininit/services/lsass/smss/winlogon/dwm/explorer`、PID 0/4、Session 0、驱动组件 |
| ⚠ 谨慎 | 有可见窗口、GPU% > 20%、有未保存状态 |
| ✓ 可关 | 无窗口 + 显存稳定 + GPU% ≈ 0 + 路径在 Temp/AppData |

> 规则永远有例外——"可关"只是建议，不是授权。

### 6.4 「易懂」表达规范

**三层信息密度**：L0 一句结论（默认）→ L1 依据（点开）→ L2 原始计数器（折叠）。

**五条铁律**
1. 不出现裸缩写（`WDDM`/`PDH`/`LUID`），必须出现时跟人话；
2. 每个判断带"因为"——"可关：无窗口、GPU 0%、装在 Temp"；
3. 数字要可感——`1.6 GB` 后补"≈ 一部 1080p 电影"；
4. **不知道就说不知道**——`—` + 原因，绝不猜（说错比不解释伤害大 10 倍）；
5. 不用恐吓词——写"会丢失进度"，不写"危险"。

**术语对照**：显存 / 共享内存（被挤到内存条的部分）/ 说不清谁占的 / 系统保留 / 关掉。

**颜色双编码**：红黄绿 + 图标 + 文字，色盲与黑白截图都能读。

### 6.5 「便捷」在不常驻下的定义

- 冷启动 ≤ 100 ms，窗口 900×520，一屏放下；
- 记住上次排序 / 筛选 / 窗口位置；
- 键盘全操作：`↑↓` 选、`空格` 勾选、`Delete` 关、`Esc` 退出、`/` 搜索；
- 失败也给下一步："它被系统保护，要以管理员重启再试吗？"

### 6.6 不做"一键清理显存"

`EmptyWorkingSet` 那套对真实显存几乎无效，甚至更慢。只提供三件真事：终止进程 / 等驱动回收 / 告诉你哪些是浪费。

## 12. 开放问题

1. **我们自己的代码要不要开源？** 建议 MIT：①缓解杀软误报 ②对借用过的项目是回馈 ③内部工具开源成本低。
   - **2026-11-14 已定：MIT**，见仓库根 `LICENSE` 与 ADR-007。
2. **要不要把 Local 补丁提 PR 给上游？** 建议跑通后再提，patch 质量更高；若合并可切回依赖、摆脱 fork。
3. **Win7 覆盖？** 不做（Tier 3 target + 无每进程显存数据）。
4. **解释库的长期维护人是谁？** 200 条规则没人更新，半年就废——这是比写代码更长期的问题。
